# Financial repair CLI freeze

This source change extends the existing `scripts.billing._mutation_policy.refuse_apply` policy to 42 additional repair CLI entry points: 16 billing apply-mode commands, three billing execute-mode commands, 19 one-off apply-mode commands, three billing financial subcommand routers and the five historical repair modes of the mixed target-shadow router. The exact entry point inventory is maintained in `tests/test_billing_repair_cli_freeze.py`. The existing three guarded commands and their tests are unchanged.

Positive write modes fail before database sessions, manifest reads, backup work or financial services are reached. `apply_billing_remediation --rollback` is also refused: rollback mutates financial history and is not an exception to the freeze. Preview behavior is otherwise preserved by this change; a preview is not thereby certified read-only, because existing commands can perform temporary or backup work. `cutover_reconstructed_balance` retains its export subcommand.

The test suite checks guard adjacency across all 42 entry points and has sensitivity controls for removed or delayed guards. Hosted AST-extracted main canaries trap database access for apply, execute and rollback paths; their preview controls establish that the trap is reachable. Independent static review and pinned Ruff passed; runtime acceptance belongs to current-head hosted CI.

This is an interim source barrier, not proof that Sub's financial authority has moved. Sub remains authoritative until the rehearsed single cutover. The financial `approve` mode of `repair_prepaid_paid_invoice_period` and `confirm` modes of `return_legacy_over_allocation` and `correct_prepaid_renewal_origin` are refused before handler dispatch. Preview/list and nonfinancial review-request creation retain their existing routes. The target-shadow router also refuses exactly `capture-renewal-terms`, `correct-renewal-terms`, `execute-reviewed-prepaid-service-renewal`, `correct-legacy-renewal-tax-invoice` and `correct-unused-prepaid-renewal`. Its other routes retain their existing owner gates; this change grants no authority to activate a ledger. Automatic writers and direct service callers still require explicit retirement or a cutover database barrier. No blocked opening account may be repaired by bypassing this policy; it belongs in the manual exceptions queue. No production writer has been activated or disabled by committing this source change.

Known owner-level gaps remain explicit: `collections.scheduled` still calls the historical renewal-term backfill, payment finalizers still invoke paid-prepaid identity repair, and the reviewed prepaid-draft web flow still calls its correction owner. A CLI guard does not stop these paths. Projection maintenance and ordinary settlement, access, timers and collections require separate classification before retirement.
