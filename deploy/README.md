# Sub deployment descriptor — evidence only, not a cutover

`deploy/product.toml` is Sub's `ProductDeploymentSpec.v1` written against the
published `dotmac-deployment-foundation==0.2.0a2` contract (Starter ADR-0070).
It was validated with that exact release's parser during authoring. It is
**not** consumed by production: root `docker-compose.yml`, `scripts/deploy.sh`
and the separate production monitor remain the live deployment path, and no
descriptor, Compose healthcheck, deployment roster, or systemd unit was
activated by adding these files.

## What is here

- `deploy/product-manifest.json` — the existing kernel-canonical release
  manifest emitted by `scripts/product_manifest.py` from
  `app.composition.SUB_ASSEMBLY` and `VERSION`; this slice only commits its
  bytes beside the descriptor and binds the descriptor to its digest.
- `deploy/product.toml` — the 13 app-owned process roles (app, eight Celery
  workers, Beat, bandwidth poller, syslog listener, profile-gated
  team-inbox SMTP at zero replicas), managed `redis-local`/`postgres-local`,
  and unmanaged VictoriaMetrics/object-store/OpenBao/GenieACS dependencies.
  Poller and syslog health reuse the merged probe owners
  (`app.services.poller_health`, `app.syslog.health`).
- `deploy/conformance-inventory.json` — generated by
  `scripts/deployment_conformance.py`; every one of the 22 root Compose
  services is classified as a descriptor role, a managed dependency, or
  excluded infrastructure with a named reason. Regenerate, never hand-edit.

## Rendered comparison (descriptor vs today's Compose)

- Same app-owned topology and commands; Celery queue split, poller and syslog
  commands, and app Uvicorn invocation are transcribed verbatim.
- Corrected targets, **not** current reality: uploads become a named volume
  (today a `./uploads` host bind), Redis/Postgres data become named volumes
  (today host paths under `/var/lib`), and hardened defaults
  (read-only root, non-root user, cap-drop ALL) apply except where a role
  declares a transcribed exception (`app` and `bandwidth-poller` NET_ADMIN,
  privileged mode, WireGuard bind mount, Docker socket, IP-forward sysctl).
- Excluded from rendering: FreeRADIUS, GenieACS + its MongoDB, Nominatim,
  VictoriaMetrics, Promtail, and vmagent (7 services) — third-party or host
  observability concerns with host networking/config bind mounts that a
  product descriptor must not silently absorb.

## Blockers that stop this descriptor being deployable

1. **Image unbound.** `[image].reference` is the all-zero sentinel. Sub's live
   path resolves the tested digest at deploy time; no committed source records
   a production digest to bind, and inventing one would be false provenance.
2. **Beat tick signal is file mtime.** `DbScheduler` entry `last_run_at`
   lives in memory; the declared tick command reads the `celerybeat-schedule`
   file mtime, which detects a dead scheduler, not a failing one.
3. **Resources are placeholders.** Root Compose declares no CPU/memory
   limits; descriptor values are conservative sizing to be confirmed against
   the production host, exactly as ERP's descriptor records.
4. **Backup retention is a count, not days.** `retention_days = 5` carries
   `DB_BACKUP_RETENTION_COUNT`'s default assuming a daily cadence; no restore
   rehearsal has ever been recorded (DB-BACKUP debt), and `encryption =
   "none"` describes today's scripts, not an approved end state.
5. **Foundation pin/workflow deferred.** Sub does not yet pin
   `dotmac-deployment-foundation==0.2.0a2` or run a conformance workflow;
   descriptor drift is guarded locally by
   `tests/architecture/test_deployment_descriptor.py` (manifest digest,
   inventory regeneration, role/Compose correspondence, migration-head
   parity) until the pin + workflow slice lands.
6. **Excluded infrastructure has no descriptor home yet.** GenieACS host
   networking, FreeRADIUS config binds, Nominatim datasets, and the
   promtail/vmagent observability pair need either managed-dependency
   declarations with real health probes or a separate host concern; the
   production monitor and systemd units are likewise not emitted.

## Migration connection material

Alembic now prefers `MIGRATION_DATABASE_URL` for both online migrations and
offline SQL generation, through the centralized `app.config.Settings` owner.
When that variable is absent, it retains the existing `DATABASE_URL` fallback
for local/developer use. A supplied empty or whitespace-only owner value
refuses migration setup with a sanitized error; it never falls back. Percent
encoding is preserved through Alembic's ConfigParser boundary. Runtime database
connections still use `DATABASE_URL` independently.

This closes the descriptor's migration-owner consumption blocker in source.
It does not provision owner credentials, activate a Foundation container,
change live deployment wiring, or demonstrate deployed migration acceptance.

## Regeneration

```bash
python -m scripts.product_manifest emit --version-file VERSION --output deploy/product-manifest.json
python -m scripts.deployment_conformance
python -m scripts.product_manifest verify --version-file VERSION --path deploy/product-manifest.json
python -m scripts.deployment_conformance --check
```

Never hand-edit `deploy/product-manifest.json` or
`deploy/conformance-inventory.json`.
