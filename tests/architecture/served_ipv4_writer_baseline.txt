# Direct writes to ``Subscription.ipv4_address`` — the served IPv4
# compatibility projection.
#
# ``network.ip_assignment_lifecycle`` owns the desired IPv4 at exact service
# grain; the column is its projection (app/models/catalog.py,
# docs/SOT_RELATIONSHIP_MAP.md, docs/designs/IP_ASSIGNMENT_LIFECYCLE_SOT.md).
# A write from anywhere else produces a served address with no IPAM record
# (the ``assignment_missing`` cohort) or one that silently disagrees with its
# assignment.
#
# This is migration debt, not permission. Counts must only shrink; a new entry
# requires an accepted deviation recorded in the lifecycle design. Removing a
# writer means deleting its line, never raising the count.
#
# Dict-driven writes (tactical stopgap, pre-Starter dotmac-ipam cut):
# ``scripts/architecture/sot_debt.py`` now also counts ``setattr(subscription,
# key|f"..._address", ...)`` loops, ``Subscription(**data)`` construction and
# ``.values(ipv4_address=...)``. Those are seeded below as current offenders:
# ``catalog/subscriptions.py`` (create ``Subscription(**data)`` and the two
# update ``setattr(subscription, key, value)`` loops; one of the three counted
# sites is the known false positive ``setattr(subscription_add_on, key, value)``,
# which has no served IP and is kept counted pending review) and
# ``provisioning_helpers.py`` (the allocator's ``setattr(subscription,
# f"{version_key}_address", ...)``, inside the owner's own path). The generic
# update loop is also closed at its input: ``SubscriptionUpdate`` rejects an
# ``ipv4_address`` change, and an IPAM-equal value is dropped, never written
# (see tests/test_subscription_ipv4_write_rejection.py). New services get their
# column from ``ip_assignment_lifecycle.project_initial_served_ipv4``.
#
# Remaining blind spot: the operator/admin form in
# ``app/services/web_catalog_subscriptions.py`` builds a payload dict whose
# ``ipv4_address`` key is only an input to the schemas above.
# Do not read a clean run as proof that this file lists every writer.
